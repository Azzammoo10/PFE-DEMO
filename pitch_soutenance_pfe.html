Cadre Conceptuel DLP
40 s ›
Boucle Continue 1. Surveiller 2. Classifier 3. Réagir 4. Analyser
Le DLP (Data Loss Prevention) est un système de protection continue qui fonctionne selon une boucle en 4 étapes : 1. Surveiller les flux en temps réel, 2. Détecter et classifier le contenu sensible, 3. Réagir immédiatement (BLOCAGE OU ALERTE), 4. Analyser les événements pour améliorer les règles.

Architecture du Laboratoire DLP (5 Volets)
2 min 30 s ›
4 VMs (192.168.100.0/24) 5 Vecteurs de Détection DLP Manager REST Pentest Metasploit Active Response Wazuh (<1.5s)
Volet 1/5 — Infrastructure & Réseau Virtualisé (4 VMs)
Laboratoire étanche sous VMware composé de 4 machines interconnectées sur un subnet dédié 192.168.100.0/24 : Ubuntu Server central (.10), Endpoints Windows 11 AMS (.20) et GO (.30), et la VM d'attaque Kali Linux (.50).
🧠 VOLET 2/5 — DLP MANAGER & MICRO-AGENTS PYTHON (CERVEAU DU PROJET) CŒUR ARCHITECTURAL
Micro-agents Python API REST Flask rules.json 3 Décisions : ALLOW / ALERT / BLOCK (403) Escalade N+1
« Ce Volet 2 constitue le cerveau central de notre architecture, découpé en 4 temps clés : 1. Capture sur l'Endpoint : Les sondes locales interceptent les actions utilisateur en arrière-plan. 2. Transport HTTP POST ➔ Serveur Central Flask : Envoi de payloads JSON normalisés vers l'API REST Flask sur le port 5000. 3. Analyse Matrice rules.json & 3 Décisions Temps Réel : • ALLOW (200) : transfert légitime autorisé. • ALERT (200) : transfert autorisé + journalisation d'alerte pour le SOC. • BLOCK (HTTP 403) : exfiltration bloquée + envoi automatique d'un mail d'escalade au responsable N+1 (gouvernance D+1). 4. Journalisation SOC : Écriture dans /var/log/dlp/dlp.json pour alimenter le SIEM Wazuh. »
Volet 3/5 — Les 5 Vecteurs de Détection (Agent Endpoint)
Couverture 360° du poste de travail pour intercepter tous les vecteurs de fuite : 1. Fichiers système (file_scanner.py via Watchdog API), 2. Médias amovibles & USB (usb_monitor.py via WMI et psutil), 3. Presse-papiers / Copier-Coller (clipboard_monitor.py via pyperclip), 4. Messagerie SMTP (email_monitor.py via Swaks), 5. Flux Web HTTP/HTTPS (dlp_addon.py via proxy mitmproxy).
Volet 4/5 — Conception de la Validation Offensive (Pentest)
Simulation d'attaques réelles depuis Kali Linux (Metasploit Multi-Handler, Reverse Shell TCP et exfiltration SCP/SSH) pour éprouver la capacité de détection du DLP et tester l'étanchéité de notre réseau.
Volet 5/5 — Supervision SOC Wazuh & Active Response (Apport du SIEM)
Centralisation et corrélation des logs JSON. Apport du SIEM : Le DLP qualifie la fuite de données, Wazuh la corréle avec l'activité système profonde (Sysmon, PowerShell) pour transformer une alerte isolée en un incident complet et déclencher l'Active Response (isolation réseau automatique en moins de 1.5s).

Les 3 Plateformes Opérationnelles
1 min 40 s ›
LabelGuard (Autolabeling IA) DLP Monitoring Tool OneTrust Tracker (RGPD)
VOLET 1/3 — LabelGuard Platform (Classificateur & Autolabeling IA)
Plateforme de génération automatique de jeux de données de test et d'autolabeling. Permet de définir les données synthétiques (IBAN, cartes bancaires), de paramétrer les seuils de confidentialité (Confidentiel, Secret) et de produire instantanément des fichiers Word, Excel, PPTX et texte prêts pour la recette DLP.
VOLET 2/3 — DLP Monitoring Tool (Supervision & Ingestion Logs)
Console centrale de supervision opérationnelle. Permet la visualisation en temps réel des logs d'incidents DLP, l'analyse de cohérence des règles Purview/Exchange et la détection automatique des conflits de politiques.
VOLET 3/3 — OneTrust Tracker (Cartographie & Conformité RGPD avec IA Locale)
Outil de cartographie des données personnelles PII et d'audit de conformité RGPD. Intègre un moteur d'IA locale (Ollama / LLM) pour le matching sémantique des règles avec gouvernance Human-in-the-Loop (arbitrage obligatoire par le RSI et traçabilité Audit Trail).

Q1
Scalabilité & Montée en Charge (Flask & JSON)
Question Piège ›
Question Jury: Montée en charge Flask/JSON PoC Lab ➔ Kafka / RabbitMQ Gunicorn WSGI Multi-Workers Incrustation Directe Wazuh Indexer
Réponse d'Ingénieur : « L'architecture Flask/JSON constitue notre Prototype de Laboratoire (PoC). Pour la production à l'échelle d'AXA (150 000+ postes), le système évoluera vers : 1. Une file de messages découpée (RabbitMQ / Apache Kafka). 2. Un serveur WSGI industriel multi-workers (Gunicorn / Nginx). 3. Une ingestion directe dans l'indexeur Wazuh Indexer / Elasticsearch sans fichier JSON plat. »
✓
Q2
Bypass par Chiffrement ou Archive Zip Mot de Passe
Question Piège ›
Question Jury: Fichiers chiffrés / .zip avec MDP Limites Inspection Contenu Complémentarité Sysmon / EDR Analyse Comportementale UEBA Wazuh
Réponse d'Ingénieur : « Tout DLP basé sur la regex/contenu a des limites sur les archives chiffrées. C'est pourquoi notre architecture est hybride avec Sysmon & Wazuh SOC : 1. Sysmon détecte l'exécution d'outils de compression anormaux ou la création d'archives chiffrées (EID 11 / EID 1). 2. L'analyse comportementale (UEBA) de Wazuh corrèle cette activité et active l'Active Response pour isoler le poste. »
✓
Q3
Inspection Trafic HTTPS / Cloud Uploads (Dropbox)
Question Piège ›
Question Jury: Exfiltration Web HTTPS Mitmproxy Proxy Interception Certificat Root CA Enterprise Déploiement GPO
Réponse d'Ingénieur : « Pour surveiller les flux web chiffrés (HTTPS/TLS) : 1. Un proxy d'interception contrôlé (Mitmproxy) est déployé. 2. Un certificat racine d'entreprise (Root CA Enterprise) est déployé sur les postes via GPO. 3. Le proxy déchiffre les requêtes HTTP POST en clair avant ré-encapsulation TLS vers le Cloud. »
✓
Q4
Confidentialité & RGPD (Presse-papiers)
Question Piège ›
Question Jury: Surveillance Presse-papiers & RGPD Minimisation RGPD (Art. 5) Analyse Volatile Locale Regex Ciblées (IBAN/CB)
Réponse d'Ingénieur : « Nous respectons le principe de minimisation du RGPD (Article 5) : 1. L'agent analyse le presse-papiers uniquement en mémoire volatile locale via des regex ciblées (IBAN, CB). 2. Aucun texte personnel non-sensible n'est jamais stocké ni transmis au serveur. 3. Seuls les événements d'alerte confirmés font l'objet d'un journal d'audit restreint SecOps. »
✓
Q5
Performances & Impact RAM/CPU sur Endpoint
Question Piège ›
Question Jury: Consommation ressources agent RAM < 45 Mo CPU < 2% Latence Isolation < 1.5s
Réponse d'Ingénieur : « Lors des tests de validation expérimentale en laboratoire : 1. Empreinte mémoire de l'agent Python : inférieure à 45 Mo de RAM. 2. Consommation processeur : inférieure à 2% de CPU en tâche de fond (hooks pywin32/Watchdog). 3. Temps de réaction de l'Active Response Wazuh : isolation du poste initiée en moins de 1.5 seconde post-détection. »
