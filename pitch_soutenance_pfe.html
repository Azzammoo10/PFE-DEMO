04
Cadre Conceptuel DLP
40 s ›
Le DLP (Data Loss Prevention) est un système de protection continue fonctionnant selon une boucle en 4 temps : 1. Surveiller les flux de données temps réel, 2. Détecter et classifier le contenu sensible, 3. Répondre immédiatement par du blocage ou des alertes, 4. Analyser les événements pour affiner les politiques.
Mots-clés Cycle Continu Surveiller les Flux Détection Contenu Réponse Automatique Analyse & Audit
05
Les 4 Piliers de Protection DLP
35 s ›
Pour éliminer tout angle mort, la protection couvre 4 piliers indissociables : — Le Cloud (SharePoint, OneDrive), — Les Données (classification et Sensitivity Labels), — Le Réseau (trafic web et messagerie Exchange), — Et les Devices (contrôle des endpoints Windows et supports USB).
Mots-clés Couverture 360° Cloud (SharePoint) Données (Labels) Réseau (Web/Mail) Devices (USB)

06
Problématique et Défis Opérationnels
50 s ›
Notre étude de l'existant a révélé quatre verrous majeurs : 1. Impact Financier : le coût extrêmement élevé des licences propriétaires du marché. 2. Souveraineté & Code : l'absence d'alternatives open-source robustes et adaptées aux grands groupes. 3. Opérations SOC : la surcharge des analystes due au triage manuel de milliers de fausses alertes. 4. Gouvernance DLP : les conflits et redondances entre règles de conformité. La question centrale a donc été : Comment offrir une protection DLP puissante, intelligente et économique sans paralyser le SOC ?
Mots-clés Coût Licences Élevé Manque d'Open-Source Surcharge Analystes SOC Conflits de Règles
07
Objectifs du Projet
40 s ›

Optimiser la gestion des règles en éliminant les redondances. 3. Automatiser le monitoring et le triage des alertes pour le SOC. 4. Faciliter la validation des SIT (Sensitive Information Types) avant leur déploiement.
Mots-clés Architecture Hybride Réduction des Coûts Automatisation SOC Validation SIT

Section 05

Anticipation des Questions Pièges ("Grillades") 🔥

Les 5 questions techniques et stratégiques redoutées par le jury senior, avec les réponses d'ingénieur béton.

Q1
Scalabilité & Montée en Charge (Flask & dlp.json)
Question Piège ›
Question du Jury :
« Votre DLP Manager s'appuie sur Flask et des logs JSON (dlp.json). Si 1 000 agents envoient 50 alertes/seconde, comment gérez-vous la montée en charge ? »
Réponse Strategique d'Ingénieur :
« L'architecture Flask/File JSON présentée constitue notre prototype de laboratoire (Proof of Concept). Pour un passage en production à l'échelle du groupe AXA (150 000+ postes), le serveur évoluera vers : 1. Une file de messages asynchrone découplée (RabbitMQ ou Apache Kafka), 2. Un serveur WSGI industriel multi-workers (Gunicorn / uWSGI avec Reverse Proxy Nginx), 3. Une ingestion directe des événements dans l'indexeur Elasticsearch / Wazuh Indexer sans passer par un fichier JSON plat local. »
Mots-clés Architecture PoC Lab RabbitMQ / Kafka Gunicorn Multi-Workers Wazuh Indexer / ES
Q2
Contournement par Chiffrement ou Archives Zip Mot de Passe
Question Piège ›
Question du Jury :
« Si un utilisateur modifie l'extension d'un fichier confidentiel (.pdf vers .dat) ou le compresse avec un mot de passe dans une archive .zip, votre agent Python le détecte-t-il ? »
Réponse Strategique d'Ingénieur :
« Tout DLP basé sur l'inspection de contenu/regex a des limites face aux flux chiffrés sans clé. C'est précisément pour cette raison que notre architecture est hybride et intègre Sysmon & Wazuh SOC ! En complément de l'agent DLP : 1. Sysmon détecte l'exécution d'outils de compression anormaux ou la création d'archives chiffrées (EID 11 / EID 1), 2. L'analyse comportementale (UEBA) de Wazuh corrèle cette activité avec le trafic réseau et déclenche l'Active Response pour bloquer le poste ou isoler la session. »
Mots-clés Limites Regex Contenu Complémentarité EDR/Sysmon Analyse UEBA Wazuh Active Response Host
Q3
Inspection du Trafic HTTPS / Cloud Uploads (Dropbox, GDrive)
Question Piège ›
Question du Jury :
« Comment inspectez-vous l'exfiltration de données vers Dropbox ou Google Drive sans casser le chiffrement SSL/TLS ? »
Réponse Strategique d'Ingénieur :
« Pour surveiller les flux web chiffrés (HTTPS/TLS), nous avons déployé un proxy d'interception contrôlé appuyé sur mitmproxy. Dans un environnement d'entreprise comme AXA : 1. Un certificat racine d'autorité de certification entreprise (Root CA) est déployé sur l'ensemble des endpoints via GPO, 2. Le proxy ré-émet des certificats à la volée pour inspecter les requêtes HTTP POST en clair avant ré-encapsulation TLS vers le Cloud destinataire. »
Mots-clés Mitmproxy Certificat Root CA Enterprise SSL/TLS Decryption Déploiement GPO Windows
Q4
Confidentialité & RGPD (Surveillance Presse-papiers)
Question Piège ›
Question du Jury :
« La surveillance continue du presse-papiers (pyperclip) ne viole-t-elle pas la vie privée et les données personnelles des collaborateurs (RGPD) ? »
Réponse Strategique d'Ingénieur :
« Nous respectons strictly le principe de minimisation du RGPD (Article 5) : 1. L'agent analyse le presse-papiers uniquement en mémoire volatile locale et filtre le contenu via des expressions régulières ciblées (IBAN, numéros de cartes bancaires), 2. Aucun texte à caractère personnel non-sensible (messages privés, emails) n'est jamais stocké ni transmis au serveur central, 3. Seules les empreintes et fragments d'alertes validées font l'objet d'un journal d'audit restreint à l'équipe SecOps. »
Mots-clés Minimisation RGPD (Art. 5) Analyse Volatile Locale Regex Ciblées (IBAN/CB) Aucun Stockage Privé
Q5
Métriques de Performance & Taux de Faux Positifs
Question Piège ›
Question du Jury :
« Quel est le taux de faux positifs de votre système et quel est son impact CPU/RAM sur le poste de travail utilisateur ? »
Réponse Strategique d'Ingénieur :
« Lors des tests de validation expérimentale en laboratoire sur 5 scénarios d'exfiltration documentés : 1. Empreinte mémoire de l'agent Python : moins de 45 Mo de RAM, 2. Consommation processeur : inférieure à 2% de CPU en tâche de fond (événements asynchrones pywin32/Watchdog), 3. Temps de réaction de l'Active Response Wazuh : isolation réseau du poste initiée en moins de 1.5 seconde post-détection. »
Mots-clés RAM Agent < 45 Mo CPU < 2% Latence Reaction < 1.5s 5 Scénarios de Test
